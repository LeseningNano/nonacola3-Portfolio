# 文章页（/news/[id]）设计方向说明

日期：2026-10-08
状态：方向稿，待用户确认后实施
涉及文件：`app/news/[id]/page.tsx`、`components/markdown-body.tsx`（短动态也用 `MarkdownBody` 的话需确认影响范围）

## 目标

1. **易读性**：中文长文读着不累，扫读时能快速找到分段。
2. **风格统一**：文章页要和 Works 页、首页 News 时间线一样，属于同一套编辑排版语言，不再像默认的 Markdown 模板。

不做的：不加评论、目录、阅读进度条、分享按钮；不改数据模型。

## 现状问题（2026-10-08 线上实测）

| 项 | 现状 | 问题 |
|---|---|---|
| 正文栏宽 | `max-w-3xl` = 768px，16px 时约 48 字/行 | 中文舒适行长约 30–40 字，太长 |
| 行高 | `leading-relaxed` = 1.625 | 对中文偏紧 |
| 正文小标题 | h3 为 18px / 粗体，上边距 24px | 和 16px 正文几乎没有层级差 |
| 配图 | 无边框、无衬底 | 深色截图和深色背景融在一起 |
| 列表 | `list-inside` | 折行后第二行不和文字对齐 |
| 图注 | 14px `neutral-500`，和图只隔 8px | 偏弱 |
| 标题区 | 36px `font-bold` Inter | 和 Works 页的细字重、紧字距大标题风格不一致 |
| 结尾 | 只有一个方框"返回主页"按钮 | 读完无路可走；按钮样式像后台 |
| 中文字体 | Inter，回落到系统字体 | 各平台效果不一致 |

## 设计方向

### 1. 版心：正文窄、媒体宽（已实施）

> 第一次试看时觉得不协调而回滚；排查后确认主要是《网站改进》一文图多字少、截图为整页截屏所致（对照 Google Blog：约 3000 字配 2 张图）。之后重新截了只含重点区域的截图并加入图组功能，再次按本方案实施（`b2fb97d`）。


- 正文栏：`max-w-[38rem]`（约 608px，16–17px 字号下约 36–38 字/行）。
- 图片和视频可以突破正文栏，放宽到约 `max-w-[52rem]`，居中显示。作品集里截图和视频是主角，应该比文字更大。
- 手机端保持现有 24px 左右边距，媒体撑满栏宽（不出血到屏幕边缘）。

### 2. 正文排版（`markdown-body.tsx`）

- 字号：手机 16px，`md` 以上 17px（与首页 News 正文 `md:text-[17px]` 一致）。
- 行高约 1.85；段间距约 `1.1em`。
- 颜色维持 `neutral-300`，强调（`strong`）用 `text-white`，不额外加粗太多。
- 中文字体栈：在 Inter 后显式补 `"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", sans-serif`，只作用于文章正文，不动全站。
- 小标题：
  - h2：约 24px（md 28px），`font-normal`，`tracking-tight`，上边距约 3.5em，下边距约 1em。
  - h3：约 19–20px，`font-medium`，上边距约 2.5em。
  - 方向是靠**字号和留白**拉开层级，不靠粗体，和 Works 页大标题用 `font-normal` 的做法保持一致。
- 列表：`list-outside pl-5`，项间距约 0.4em，`marker:text-neutral-600`。
- 引用：保留左竖线，正文颜色降到 `neutral-400`，字号不变，上下留白加大。
- 行内代码和代码块：保持现状，只微调间距。

### 3. 图片 / 视频

- 外面包一层容器：`border border-neutral-800` 加很淡的底色（如 `bg-neutral-900/40`），截图和背景之间有一条明确边界。
- 图注：13px，`neutral-500`，和图相隔约 12px；左对齐，并加一个等宽小字的序号前缀（如 `FIG. 01`），呼应 Works 页的等宽小标签。序号按出现顺序自动编号。
- `<video>` 套用同样的容器和图注规则。

### 4. 标题区（`page.tsx`）

参考 Works 页的 `works-intro` 和首页 News 时间线：

```
[等宽小字] 2026.10.07 · 公告          ← text-xs tracking-[0.24em] neutral-500，标签不再用方框
[大标题]   网站改进                    ← font-normal tracking-[-0.03em]，手机 36px / 桌面 56–60px，白色
[细分隔线] ─────────────               ← border-neutral-800，和正文间隔约 48–64px
```

- 日期改成 `2026.10.07` 这种等宽数字格式，和首页时间线的日期统一。
- 标题字重从 bold 改成 normal，这是和站点风格对齐最关键的一处。
- 不加封面图（数据模型里没有这个字段，本轮不扩展）。

### 5. 结尾导航

- 正文结束后放一条细分隔线，下面是两栏：**← 上一篇 / 下一篇 →**，显示等宽小字"PREV / NEXT"加文章标题；没有的一侧留空。
- 再下面放一个文字链接"← 返回 News"，跳到首页 News 区块的锚点；不再用方框按钮。
- 上一篇/下一篇只在已发布且 `title !== null` 的文章之间按 `createdAt` 排序。需要在 `lib/data.ts` 新增一个带 `posts` 缓存标签的读取函数，保证写操作调用 `revalidateTags("posts")` 后能刷新。

## 实施顺序建议

1. **易读性**（低风险，单文件）：`markdown-body.tsx` 的字号、行高、小标题、列表、图片容器和图注。
2. **版心**：调整 `page.tsx` 的正文栏和媒体宽度规则。
3. **标题区**：调整元信息行和标题样式。
4. **结尾导航**：新增数据函数和上一篇/下一篇组件，并补测试。

每一步做完都在桌面和 375px 手机宽度下截图对比。线上已有的《网站改进》文章（4 张截图、1 个 h3）适合当回归样本。

## 待确认

- 图注是否要 `FIG. 01` 编号前缀，还是只保留文字。
- 媒体放宽到 52rem 是否会让竖版截图过高；可以考虑对竖图限制 `max-h`。
- `MarkdownBody` 还用在后台的 `components/markdown-editor.tsx:306` 和 `components/admin/article-editor.tsx:185`，这两处都是预览。建议让预览也同步新排版，做到所见即所得。但"媒体放宽到 52rem"依赖页面版心，不应该写进 `MarkdownBody` 本身，可以通过 `page.tsx` 的容器或一个可选的 `variant` 来控制。
