# Dashboard「剪辑台」视觉重设计

**日期：** 2026-09-29

**状态：** 方向与 6 个设计段均已由用户在对话中逐段确认；用户授权写完本文档后直接实施。

**范围：** 私有后台（`/login`、`/dashboard/*`）的视觉系统、页面层级与部分界面结构。不含前台、API、数据模型。

## 1. 背景与目标

上一轮（2026-09-22 spec）把后台整理成了 Linear/Vercel 式的克制界面，功能完整，但用户认为：

- **太平庸、像模板**：基本是 shadcn 暗色默认样式，与前台的影像气质和 Bitcount 像素字体没有联系。
- **层级乱、不好扫读**：页头、分区、列表都靠 `white/10` 细线分隔，字号集中在 10–14px，主次不清。

线上实测（1440 宽）还发现：作品缩略图只有约 72px；News 两种类型混排时列不对齐、徽标挤成一团；作品编辑页标题重复两次、同一媒体地址出现四次；页面媒体两个大黑框加整段 Blob 地址。

**目标：** 用「剪辑台」方向重做后台界面，让它有作品集主人自己的辨识度，并让每一屏的主次一眼可辨。所有业务行为保持不变。

**成功标准：**

- 每个后台页面都明显属于同一套视觉系统，并与前台（黑底、Bitcount）气质相连。
- 每屏最多一个橙色主操作；状态用「点 + 文字」表达，扫读时能快速分出缩略图 → 标题 → 等宽元数据 → 状态。
- 编辑器里每个媒体字段只出现一次；原始 URL 默认不展示。
- 现有鉴权、离开保护、保存失败保留输入、媒体删除复核、Hero `posterUrl` 兼容规则全部不变。

## 2. 已确认的决定

| 事项 | 决定 |
|---|---|
| 视觉方向 | A「剪辑台」：像剪辑软件的素材面板 |
| 标题语言 | 英文像素标题（WORKS / NEWS / ORDER / PAGE MEDIA / LIBRARY）+ 中文副标题；其余界面文字全中文；侧栏分组仍为中文 |
| 结构调整 | 编辑器媒体字段精简、页面媒体紧凑化、登录页重做、News 列表重排（四项全做） |
| 实现方式 | 后台专属 CSS 变量 + 一小套共享组件；前台与业务逻辑不动 |

## 3. 视觉系统

### 3.1 颜色

表面层级靠底色区分，细线只在必要处使用。

| 变量 | 值 | 用途 |
|---|---|---|
| `--admin-canvas` | `#0b0b0c` | 内容区画布 |
| `--admin-panel` | `#111113` | 侧栏、吸顶栏、工具栏、面板组 |
| `--admin-raised` | `#16161a` | 悬停行、输入框、次要按钮、卡片 |
| `--admin-selected` | `#1c1c21` | 选中导航、选中筛选 |
| `--admin-line` | `#222227` | 必要的分隔线 |
| `--admin-line-strong` | `#2e2e35` | 输入框、次要按钮描边 |
| `--admin-fg` | `#ededee` | 主文字 |
| `--admin-fg-2` | `#a1a1a8` | 次要文字、标签 |
| `--admin-fg-3` | `#7a7a83` | 元数据（在画布上对比度 ≥ 4.5:1） |
| `--admin-accent` | `#ff5a1f` | 信号橙：主按钮、精选、未保存、焦点、导航选中条 |
| `--admin-accent-fg` | `#1a0800` | 橙底上的文字 |
| `--admin-accent-text` | `#ff8a5c` | 橙色文字（状态文字） |
| `--admin-success` | `#3ecf8e`（文字 `#5fd49a`） | 已发布、成功 |
| `--admin-danger` | `#f2555a` | 错误、删除；与橙色明显区分 |

语义约定：橙 = 需要你处理/主操作；绿 = 已发布；灰空心点 = 普通/草稿/已保存；红 = 错误与破坏性操作。

### 3.2 字体

- **Bitcount Grid Single（像素）**：只用于英文页标题（约 28px）与 nonacola3 字标。已由根布局以 `--font-bitcount` 提供。本地 dev 下可能不生效，线上正常（已知情况）。
- **JetBrains Mono（等宽）**：只用于日期（`2026.09.24`）、数量、文件大小、文件名、地址、分区编号（`01`）、面包屑前缀（`WORKS /`）。
- **Inter + 系统中文字体**：其余界面文字。最小字号 12px；行标题 14px；正文输入 13–16px。

### 3.3 形状、阴影、动效

- 控件与列表行圆角 4px；面板、弹窗 8px。
- 只有弹出菜单与弹窗有阴影。
- 动效仅保留 120–160ms 的悬停与展开；遵守 `prefers-reduced-motion`。
- 焦点：2px 信号橙 outline，offset 2px，所有可交互元素可见。

### 3.4 共享组件的视觉规则

- **按钮**：主按钮橙底深字，每屏最多一个处于橙色状态；次要按钮为抬升底 + 强描边；幽灵按钮只有文字/图标，悬停出底色。
- **状态点**：7px 实心点（精选橙、已发布绿、失败红、未保存橙）或空心灰点（普通、草稿、已保存）+ 12px 文字。取代现有胶囊徽标。
- **筛选组**：选中项为选中底色，每项后跟等宽数量。
- **页头**：左侧英文像素标题 + 中文副标题 + 下一行等宽统计；右侧只放一个主操作。
- **空状态**：区分「还没有内容」（说明 + 主按钮）与「筛选无结果」（`没有匹配「关键词」的…` + 清除筛选）。

## 4. 外壳与登录页

### 4.1 桌面侧栏

- 宽约 200px，面板底色，右侧一条分隔线。
- 顶部：像素字 `nonacola3` 字标 + 12px「管理后台」，替换现有 N3 方块与 Portfolio 字样。
- 分组「内容 / 网站 / 资源」，12px 灰字。
- 导航项高 34px，图标 + 中文名；选中：选中底色 + 左侧 2px 橙条 + 白字；悬停：抬升底色。
- 不在侧栏显示数量（避免布局每次导航都额外查库），数量由各页页头显示。
- 底部账号行：首字母方块 + 用户名 + 「查看网站」图标按钮 + 「退出登录」图标按钮，均有可见提示与 `aria-label`。

### 4.2 内容区

- 列表页内容最大宽度约 1200px；编辑器自行控制宽度。
- 桌面端内容区左右留白保持一致。

### 4.3 移动端

- 顶部 56px 条（沿用现有高度，编辑器吸顶偏移依赖它）：左字标、右菜单按钮；抽屉内容与桌面侧栏一致。
- 保持现有抽屉的焦点锁定、Esc 关闭、焦点归还。

### 4.4 登录页

- `/login` 加入后台路径判断（`isAdminPath`），前台导航栏不再出现。
- 画布居中约 360px 面板：像素字标、「管理后台登录」、用户名与密码输入框、错误提示（红色，位于按钮上方，`role="alert"`）、全宽橙色「登录」按钮。
- 输入框补 `autocomplete="username"` / `autocomplete="current-password"`；用户名框自动聚焦。
- 登录逻辑不变：`signIn("credentials", { redirect: false })`，成功后跳转 `/dashboard`。

## 5. 列表页

### 5.1 共同规则

- 行与行之间不画横线；每行是 4px 圆角区域，悬停换抬升底色。
- 缩略图与标题为编辑链接；预览、更多（⋯）按钮常显但颜色较淡，不依赖悬停。
- 工具栏在面板底色条上：左筛选组（带数量），右带图标的搜索框与次要操作。
- 删除仍使用浏览器 `confirm`（换成自定义弹窗不在本轮范围）。

### 5.2 作品（`/dashboard/works`）

- 页头 `WORKS` / 作品 / `7 个作品 · 3 个精选`；主操作「新建作品」。
- 行：112px 16:9 缩略图（缺失时胶片图标占位）→ 标题 14px + 等宽元数据（分类 · 职责 · 工具）→ 状态点（精选/普通）→ 最后更新日期（等宽）→ 预览、⋯（删除）。
- 工具栏：全部 / 精选 筛选，搜索，次要操作「调整顺序」。
- 移动端：96px 缩略图，状态点移到标题下，预览收进 ⋯ 菜单。

### 5.3 调整顺序（`/dashboard/works/order`）

- 页头 `ORDER` / 调整顺序，附返回作品链接。
- 行：拖动把手、等宽序号 `01`…、80px 缩略图、标题、精选开关（开为橙）、上移、下移。插入线为橙色。
- 有改动时底部吸底保存条：左「排序有未保存的更改」+ 橙点，右「取消」与橙色「保存排序」；保存失败提示并保留改动。
- 保留键盘与移动端上下移按钮及其 `aria-label`。

### 5.4 News（`/dashboard/news`）

- 页头 `NEWS` / 动态与文章 / 统计；主操作「+ 新建」菜单：短动态、Markdown 文章。
- 行固定列宽：32px 类型图标方块（文章＝文档图标，短动态＝气泡图标，带屏幕阅读器文字）→ 标题（文章第二行摘要；短动态显示正文开头）→ 标签 → 状态点（已发布/草稿）→ 日期 → 预览（仅已发布）、⋯（发布/转为草稿、删除）。
- 删除原「文章 / 短动态」类型胶囊。
- 筛选：全部 / 已发布 / 草稿，带数量。

### 5.5 媒体库（`/dashboard/media`）

- 页头 `LIBRARY` / 媒体库 / `63 个文件 · 812.4 MB`；主操作「上传」菜单：图片、视频。「刷新」改为工具栏图标按钮。
- 筛选：全部 / 图片 / 视频 / 未使用，带数量；按文件名搜索。
- 自适应瓦片网格（最小约 200px）：16:9 预览、左上类型标、等宽文件名（完整名在 `title`）、大小、引用情况（`使用中 · 作品缩略图`），未使用时显示红色「删除」。
- 删除前的服务端引用复核、409 冲突处理、失败恢复与重试逻辑不变。
- 加载骨架与瓦片同形。

## 6. 编辑器与媒体控件

### 6.1 共用框架

- 删除编辑/新建路由外层的 `AdminPageHeader`（如「编辑：…」），页面只有一条吸顶操作栏。
- 操作栏（面板底色）：左侧返回按钮、`WORKS /` 或 `NEWS /` 等宽前缀 + 标题、下方保存状态点；右侧查看公开页面（幽灵）、次要按钮、橙色主按钮。
- 保存状态：已保存（灰）、有未保存更改（橙）、保存中…、保存失败（红）；失败时栏下出现红色提示，所有字段保留。
- 表单分区：`01 基本信息` 式等宽编号标题 + 一条淡分隔线；取消现有「说明在左、字段在右」的三栏布局；短字段两两并排。

### 6.2 作品编辑器

- ≥1280px：左表单（最宽约 720px）+ 右约 380px 吸顶卡片预览（保留桌面/移动宽度切换）；更窄时预览在表单下方、可折叠。
- 分区：`01` 基本信息（标题；分类 + 日期；精选开关）、`02` 媒体（作品视频、缩略图）、`03` 卡片信息（摘要；职责 + 工具）、`04` Case Study（Markdown）。
- 按钮：查看公开页面、保存并返回、保存更改（行为不变）。

### 6.3 MediaField（新共享组件）

- 每个媒体字段一个槽：左 16:9 小预览，右来源说明与按钮。
- 来源识别（纯函数 `describeMediaSource(url)`，位于 `lib/admin-media-source.ts`）：
  - Vercel Blob 文件：真实缩略图 / 视频首帧 + 等宽文件名；
  - Bilibili / YouTube：平台图标 + `Bilibili · BV…` / `YouTube · <id>`（不抓取平台封面）；
  - 其他链接：域名；
  - 空：虚线框 +「未设置」。
- 按钮：「从媒体库选择」（打开选择器，内含上传）、「编辑地址」（展开后才显示原始 URL 输入框）、「清除」（仅选填字段）。
- `MediaPicker` 拆为只负责弹窗的组件，触发按钮由调用方提供；媒体库上传入口与页面媒体复用同一弹窗逻辑。
- 选择器弹窗：瓦片与媒体库一致，当前选中项橙色描边并标「当前」；上传进度条为橙色。上传类型校验与 `accept` 过滤不变。

### 6.4 文章编辑器

- 标题为 22px 大号无边框输入框，其下一行较窄的标签输入框。
- 宽屏左 Markdown 编辑、右实时预览；窄屏上下排列。
- 按钮随发布状态（逻辑不变）：草稿 →「保存草稿」+ 橙色「发布」；已发布 →「转为草稿」+ 橙色「保存更改」。

### 6.5 短动态编辑器

- 居中约 640px 单栏：16px 正文、右下等宽字数、下方标签框；操作栏同文章。
- `/dashboard/news/new`（无类型参数）保留为兼容选择页，改为两块同风格瓦片。

## 7. 页面媒体（`/dashboard/settings`）

- 页头 `PAGE MEDIA` / 页面媒体 /「首页和 Works 页使用的影片素材，保存后才会发布。」
- 两个面板组：
  - **首页 Hero**：背景视频、封面图片两个素材槽，一次请求一起保存。
  - **Works Showreel**：右上「嵌入链接 / 上传视频」切换，一个素材槽。
- 素材槽为 MediaField 的放大版（约 200px 预览），窄屏上下排列。
- 预览：Hero 视频以当前（草稿）封面为底图、点击才播放、`preload="metadata"`，右下显示等宽时长（加载元数据后可得）；封面未自定义时标「默认封面」。
- 草稿与已保存不同时：预览橙色描边 +「待保存」标签；说明行「当前 X → 待保存 Y」；出现「撤销」，只把该槽恢复为已保存值。
- 为此在 `lib/admin-settings.ts` 增加单项恢复事件；恢复后若与已保存值完全一致，整组状态回到已保存。
- 每组底部保存条：左状态（`1 项待保存` / 已保存 / 保存中… / 保存失败 + 原因），右「保存 Hero」/「保存 Showreel」；仅该组有改动时为橙色主按钮。
- 删除现有 `SourceDetails` 整段地址展示与上下重复的预览。
- 不变：路由、两个保存接口与请求体、缓存失效、`posterUrl` 兼容规则、媒体库引用保护、失败时保留两个草稿。

## 8. 技术方案

### 8.1 样式接入

- `app/globals.css` 增加独立的后台样式块：
  - `--admin-*` 色板变量；
  - `@theme inline` 映射为 Tailwind 工具类（如 `bg-admin-panel`、`text-admin-fg-3`、`font-pixel`、`font-admin-mono`）；
  - `:root:has([data-admin-theme])` 下覆盖 shadcn 变量（`--background`、`--foreground`、`--primary`、`--primary-foreground`、`--secondary`、`--muted`、`--muted-foreground`、`--accent`、`--border`、`--input`、`--ring`、`--popover`、`--popover-foreground`、`--card`、`--destructive`），使 Portal 渲染到 `body` 下的 Dialog/Menu 也采用后台外观；仅当后台外壳或登录页挂载时生效。
- `AdminShell` 根节点与登录页根节点加 `data-admin-theme`。
- JetBrains Mono 通过 `next/font/google` 在根布局声明，`preload: false`，变量挂在 `body`；前台不使用该字体，不会下载。这是根布局唯一改动。
- 实施前按 AGENTS.md 阅读 `node_modules/next/dist/docs/` 中 `next/font` 与布局相关文档。

### 8.2 文件变更

- **新增**：共享组件（页头、状态点、筛选组、搜索框、空状态）、`components/admin/media-field.tsx`、`lib/admin-media-source.ts`。
- **重写界面层**：`admin-shell`、`admin-editor-header`、`admin-form-section`、`admin-page-header`、`works-list`、`work-order-editor`、`news-list`、`media-library`、`media-picker`、`page-settings`、`work-editor`、`article-editor`、`short-post-editor`、`work-card-preview`、`admin-media-skeleton`、三个 `loading.tsx`、`login/page.tsx`、`news/new/page.tsx`、作品与 News 的编辑/新建路由页。
- **lib 仅两处改动**：`isAdminPath` 增加 `/login`；`admin-settings` 增加单项恢复事件。
- **不动**：所有 API 路由、`lib/schemas.ts`、Prisma、鉴权三层、`proxy.ts`、缓存标签、`lib/admin-works` / `admin-news` / `admin-media` 业务逻辑、前台组件。
- `AdminStatusBadge` 被状态点取代；保留 `data-admin-status` 数据属性约定。

### 8.3 测试

- 旧测试中用正则锁定旧类名/结构的断言（如 `rounded-full`、`top-14`、`xl:top-24`、`<details open`、`AdminStatusBadge`、`md:px-6`）改为检查新组件约定。
- 行为类断言一律保留：离开保护注册、编辑链接、上移/下移 `aria-label`、「保存排序」、新建类型链接、加载状态 `role="status"` 等。
- 新增：`describeMediaSource` 各来源、单项恢复事件、状态点各状态、`isAdminPath("/login")`、页头渲染、MediaField 空/媒体库/嵌入三态。

### 8.4 开发流程

- 在功能分支上进行，不直接改 `master`。
- 顺序：变量与基础组件 → 外壳与登录 → 列表 → 编辑器与 MediaField → 页面媒体 → 测试整理；每步一个提交、每步跑测试。
- 合并推送 `master` 前再征求用户同意。
